# 命令执行与结果反馈规范

[English](command-execution.md) | 中文

## 摘要

本项目的智能体、命令包装器及其他工具遵循相同的结果反馈规则：完整操作日志保留在执行端，成功返回简短摘要，失败返回有限诊断，查询返回完成任务所需的数据。运行期间等待完成或状态变化，避免反复读取相同输出。用户明确要求完整输出时，以用户要求为准。

<a id="scope"></a>
## 适用范围与输出模式

本规范约束构建、测试、lint、类型检查、文档生成与校验、依赖安装、打包、启动检查及其他操作命令，也约束智能体对这些工具结果的读取。采用何种反馈方式由任务目的决定，不由命令名称或退出码决定；命令可同时产生操作日志和任务需要的数据。

| 模式 | 场景 | 交给模型的内容 |
|---|---|---|
| 摘要 | 构建、检查、安装、文档生成等操作 | 终态、耗时、必要统计、预期校验、产物及日志位置 |
| 数据 | 查分支、读代码、查询配置、提取所需信息 | 与任务相关的数据；较大结果先筛选、分页或返回可读取资源 |
| 交互／流式 | 必须输入的交互命令、服务启动或持续运行进程 | 必需提示、就绪信息或有意义的状态变化；常规进度与重复输出留在日志 |

源码、配置、查询结果或文档正文是任务输入时，不能因为命令成功而隐藏它们。诊断输出不等于查询数据；读取一份文件也不意味着必须输出整个目录或整个仓库。先限定文件、搜索范围和字段，独立的必要查询可批量执行。

<a id="waiting"></a>
## 执行与等待

操作命令启动前确定日志位置和成功预期。stdout 与 stderr 保存为本次独立日志或执行端可访问资源，避免先完整输出到模型上下文后再做摘要。保留真实退出码、信号、取消及启动异常，不能用重定向或管道误报最后一个辅助命令的退出状态。

优先使用工具提供的进程会话、完成事件或状态等待。运行期间不反复读取日志末尾来判断是否结束，不读取已经交付过的相同片段。必须轮询时只查运行状态并采用合理间隔；只有新阶段、失败、异常停滞或需要输入时读取相关输出。长任务的用户进度说明可以报告仍在运行及已知阶段，不需要向模型回传常规日志；等待长度遵守所在智能体环境的沟通与中断要求。

有足够结果后停止读取：成功且预期满足，不再打开成功日志；失败信息足以采取修复行动，不继续浏览无关日志。任务期间的状态请求不应触发重复检查、重复命令或额外全量日志读取。只在新的改动、失败、异常或未满足预期需要时重跑检查。

持续运行进程区分“进程存在”“服务就绪”和“已完成”。启动任务按预先指定的就绪探测验收，不能把未退出当成功，也不等待长期服务自行结束。后续输出落盘，服务失败、就绪探测失败或必要状态变化单独报告。

<a id="results"></a>
## 成功预期与结果摘要

退出码为零是操作成功的必要证据之一，不能代替任务要求。检查应满足可验证的预期；预期使用项目配置、工具声明或当前任务要求，不能为了显示成功而事后降低。不同命令不强制执行相同校验，也不额外扩大原有检查范围。

| 操作 | 需要验证的预期示例 |
|---|---|
| 测试 | 选中的项目确实匹配，实际执行了预期测试，失败数为零；允许跳过的项如实报告 |
| 构建 | 要求的产物存在且属于本次有效构建或经验证的复用；必要冒烟独立报告 |
| 文档生成／更新 | 所需文件存在，声明的同步或配对检查通过；未通过的校验不隐藏 |
| 安装／打包 | 所需包或包文件存在，目标及版本符合要求 |
| 服务启动 | 就绪探测成功，使用的地址或入口明确 |

“没有匹配项目”“未执行测试”“缺少产物”“意外跳过检查”等情况按预期未满足报告，即使命令退出码为零。预期无法验证时明确写明未验证，不宣称通过。一个检查通过不推导功能通过、全部测试通过或部署完成。

成功摘要包含操作及范围、终态、耗时、必要统计、预期校验、必要产物和日志位置。未知字段省略或明确表示未知，不能补造测试数量或耗时。每个检查单独保留状态；多命令汇总只展开失败或预期未满足项，仍列出取消及必要的跳过情况。

以下为统一结果字段的建议约定，并非当前所有工具已经实现的 JSON 接口。现有工具可以提供等价的简短文本，不要求改造后才开始遵守本规范。状态区分 running、ready、passed、failed、cancelled、unmet-expectation；就绪只适用于持续运行进程，预期未满足不改变真实退出码。

```json
{
  "operation": "unit-tests",
  "scope": "personal-assistant",
  "status": "passed",
  "exitCode": 0,
  "durationMs": 1200,
  "summary": { "passed": 28, "failed": 0, "skipped": 0 },
  "expectations": { "status": "satisfied" },
  "artifacts": [],
  "logPath": "/absolute/path/to/run.log",
  "diagnostics": []
}
```

<a id="diagnostics"></a>
## 失败诊断与日志读取

首次失败反馈包含操作、范围、真实退出状态、失败项、日志位置和足够定位问题的诊断。默认片段最多 80 行且最多 12000 字节，与当前静默包装入口上限一致；优先使用更短、直接相关的片段。保留错误位置、错误码、关键消息及必要堆栈；只取最后几行时不能假装已经找到根因。

信息不足时，先按失败检查、包名、文件、错误码或阶段在保存日志中搜索，再读取命中处的有限上下文。每次读取回答一个具体诊断问题，避免完整 cat、大段尾部或重复读取同一内容。结果过大时进一步定位或分页；只有完整内容确为当前任务必需或用户明确要求时才扩大范围。

编译失败、测试失败、预期未满足和环境限制分别报告。权限、网络、IPC 或其他宿主沙箱问题按根 AGENTS.md 的现有重试规则处理；诊断裁剪不能隐藏失败、绕过产品沙箱、禁用校验或用静默重跑替换真实结果。取消保留 cancelled，不伪装成成功或普通失败。

<a id="logs"></a>
## 日志保留与敏感信息

每次执行使用独立日志位置，并行运行不能相互覆写。仓库内日志放在 Git 忽略的目录；`.dsh-build/build-logs/` 是当前根脚本包装入口的目录，其他工具使用合适的已忽略目录或执行资源。报告可定位的绝对路径或资源标识，调查结束前保留日志。删除或保留期限由工具策略和用户要求决定，不删除其他任务的日志。

日志落盘不是脱敏。避免记录凭据或不必要的私人内容；必要诊断返回模型前去除无关敏感值。用户要求完整输出也不解除已有凭据保护要求。保留可诊断的文件、行号、错误类型和必要上下文，不能把错误内容全部抹掉。

<a id="tools"></a>
## 工具职责与当前入口

| 层级 | 职责 |
|---|---|
| 执行工具／包装器 | 日志落盘、进程等待、退出／信号／取消、耗时、诊断上限和资源位置 |
| 命令适配器 | 提取测试统计、编译错误、生成产物、检查状态；解析失败不伪造结构化结果 |
| 项目／任务配置 | 指定实际命令、范围、所需产物、就绪条件与允许跳过的条件 |
| 智能体 | 选择摘要／数据／交互方式；只读取必要结果；如实报告已执行检查及限制 |

现有根脚本可使用 `pnpm run build:quiet -- <script> [arguments]` 保存输出，它已用于 `build:local`，也支持其他有限运行的根 package 脚本。日常构建入口及当前包装器行为见[日常本地构建](cookbook/local-builds.zh.md)。该包装器目前返回退出状态、耗时、日志及有限失败尾部，不自动解析测试统计或验证全部成功预期，使用方仍须完成适用的验证。

本规范不新增 run:quiet 命令，也不声称所有工具已经自动适配。不经过当前根脚本包装器的命令，应使用等价的文件或资源输出方式并保存正确退出状态；持续进程保存输出并提供就绪探测；查询返回必要数据。新增工具和后续改造均遵守这些规则，不需要每个功能重新制定日志反馈策略。

<a id="checklist"></a>
## 执行检查表

1. 明确任务需要操作摘要、查询数据还是交互输出，并选择最小必要范围。
2. 操作日志在执行端保存，启动后等待完成或有意义的状态变化。
3. 完成后检查真实退出状态和适用成功预期，区分通过、失败、取消和预期未满足。
4. 成功只接收摘要；失败先接收有限诊断，信息不足再定向读取。
5. 结果足够后停止读取和重复运行，报告检查范围、结果及必要日志位置。
