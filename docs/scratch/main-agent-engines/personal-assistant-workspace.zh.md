## 概述

个人助理页面呈三栏：中栏展示完整对话与模型回复，共享右侧栏的助理标签页承载任务面板，提供状态摘要、筛选与验收操作；助理页激活时自动展开该栏。助理拥有固定工作目录和跨项目复用的固定会话；任务执行使用独立项目会话，用户可以按需查看完整过程。（初稿的上下分区方案已被上述三栏布局取代，仅作设计过程记录。）

## 页面与交互

页面顶部保留“个人助理”标题与服务状态。主体上方为任务管理区，下方为助理对话区，两区有可拖动分隔线，初始约七成高度用于任务、三成用于对话。比例为可配置展示偏好，不硬编码为业务规则；小窗口按最小可用高度调整，两个区域分别滚动，输入框保持可见。

任务区依次展示状态摘要、搜索／筛选和任务列表。摘要包含待执行、执行中、待验收、需要处理、已完成数量；待验收与需要处理优先可见。默认展示未结束任务，已完成和已取消可通过筛选查看，全部计数始终可见。支持按项目和状态筛选，搜索标题与描述。

列表每项显示标题、项目、状态、最近更新时间和当前执行摘要。宽屏采用紧凑行，窄屏自动变为卡片；长描述在详情展开。任务状态来自持久任务记录，不能通过模型回复中的“已完成”文字改变。

点击任务展开内嵌详情，包括描述、执行记录、结果摘要、错误及当前支持的操作。右侧默认不占据常驻空间；需要完整执行对话时打开对应项目会话或通用详情侧栏。离开再返回主页保留所选任务、筛选及上下区比例。

提供新增任务、编辑标题／描述、选择项目、启动、停止、接受结果、取消及重新打开等与现有 Host 能力对应的入口。运行中停止与任务取消须分别表达；操作可用性由 Host 校验，客户端等待期间禁用重复提交，失败在任务附近展示原因。

用户可以通过下方对话描述任务，也可以使用列表操作。对话创建或更新任务成功后，以结构化操作结果关联对应任务，任务区刷新并短暂高亮；选中任务发送给模型时，通过显式“针对该任务提问”操作附带任务 ID，不把客户端选中项作为未记录的隐藏提示。

## 紧凑对话与回复展示

下方默认展示最近一次用户请求、助理回复预览及输入框；较早历史在“查看完整对话”中展开。助理回复以有限行数展示，附带完整内容入口；执行工具日志默认折叠。第一版使用确定性的文本截断和已有结构化结果卡，不额外调用模型生成摘要，避免摘要新增成本或遗漏承诺。

任务变更卡显示创建、开始、状态更新等实际工具结果，并链接到任务；普通文字回复仍提供预览。长回复、代码块和文件内容按需展开；原始消息与日志完整保留。流式输出可查看最新内容，用户手动查看历史时不强制跳回底部。

授权、模型提问、错误、恢复提示、中止按钮和验收请求保持可见，不能被一般回复折叠规则隐藏。支持一键展开对话占据主体和返回任务布局，保留输入草稿、滚动及焦点；模型控制复用已有组件，助理引擎仍固定 Native。

## 固定工作目录与全局固定会话

“全局”指同一个 DSH_HOME 下、同一个助理任务存储对应一个 coordinatorSessionId，跨项目、页面切换、重启以及共享该 home 的 Web/Desktop 复用。不同 DSH_HOME 或显式不同 dataDirectory 保持各自独立；不建立跨账号、跨主机的隐式全局会话。

新增可选配置 assistantWorkingDirectory。默认解析为个人助理 dataDirectory 下的 workspace，即通常为 <DSH_HOME>/personal-assistant/workspace；首次启动由 Host 创建该专属目录。显式配置必须解析为有效绝对目录并验证可用，配置错误明确报出，不能退回启动进程 cwd。

助理会话创建时显式传入 engineId=native 和固定 cwd，不绑定当前选中的项目 workspaceId。UI 隐藏工作区切换并提供只读目录信息。所有协调操作使用该持久会话；具体执行任务继续按 task.workspaceId 创建独立项目会话，每次执行记录自己的 Session ID。

助理目录用于协调时必要的本地文件与上下文，不把任务 JSON 或账号配置暴露为普通工作文件；它不是安全隔离措施。涉及项目修改应通过项目执行会话进行，模型可以查询注册项目和选择任务项目。修改助理 cwd 不应改变已存在执行会话的工作目录。

创建、查询和恢复由 Host 单一入口负责，并在现有跨进程文件锁下复用或创建会话。客户端移除“目录中找不到便创建新会话”的路径：目录暂不可见时保留原 ID 并重试加载，网络／授权错误不能替换全局会话。多个客户端并发打开只能得到同一个 ID。

旧协调会话的 cwd 与目标一致时直接复用；不一致时不修改历史身份，执行一次显式迁移：在锁内创建目标目录的新协调会话、保存旧引用和原因并保留旧日志。任务集合与执行记录保持关联，新会话通过已有工具读取任务，不能声称继承旧对话记忆。UI 提示更换原因并提供查看旧对话入口。

显式修改 assistantWorkingDirectory 后重启配置，在确认生效前按上述规则更换协调会话并提示；不同 Host 对同一存储配置不同目录时应报配置冲突，不能反复替换。历史损坏恢复同样使用固定 cwd，保留现有每次客户端激活至多一次自动恢复的保护。目录不可访问时阻止协调会话启动并给出修复入口，不静默清空数据。

存储扩展需记录已确认的目录身份及更换原因；新增原因不能冒用 corrupt-history。实施时检查严格 stateSchema 的兼容性，按项目持久类型规则确认是否需要版本化迁移及升级指南。不得直接覆盖旧 Session 日志或无条件重置 tasks.v1.json。

## 数据刷新与多端操作

任务面板读取 Host dashboardSnapshot，页面激活时刷新，并在可见期间按现有 pollIntervalMs 刷新；操作成功立即刷新，切到后台暂停，重新激活恢复。取消过期请求，协调会话替换后拒绝旧 epoch 的响应；不以轮询失败清空已有列表。

Web/Desktop 共用任务文件与会话时，沿用 Host 文件锁和任务状态校验。会话 prompt、排队和中止复用现有 Session 调度，展示同一助理正在响应的状态，不新增第二个协调智能体。执行会话停止不代表任务已经验收完成。

## 实现范围与归属

主要改动归 personal-assistant 插件：任务列表、详情、刷新、固定目录配置、Host 会话生命周期及恢复。上下分区与紧凑对话优先复用通用组件；若 conversation.shell 缺少紧凑模式，应新增显式宿主展示选项并维持默认会话行为，不用 CSS 隐藏关键控制或复制消息渲染器。

实施顺序为固定目录及单一协调会话创建、任务主页与刷新、紧凑回复和任务定位、恢复迁移与多端验收。保留个人助理现有任务状态与项目执行机制；Agent Team 图和折叠方案另见[独立设计](team-panel-flow.zh.md)。

## 验收与功能状态

布局验收覆盖宽窄窗口、可拖动分区、任务筛选、待验收突出展示、完整回复展开、输入草稿和焦点、授权及错误可见、中英文及明暗主题。任务操作须以 Host 成功结果刷新，任务执行结束进入 review，用户接受后才进入 done。

会话验收覆盖不同启动目录、项目切换、重启、Web/Desktop 并发打开同一 ID、目录不可访问、配置冲突、旧目录一次迁移及历史损坏恢复；恢复与首次创建必须传入同一固定 cwd，任务项目执行仍使用正确项目目录。

实施时补齐相应生命周期测试、客户端行为测试及用户可见输出快照。当前只完成源码核对与设计，功能清单记录“设计完成，待实现”，验证后更新同一条目为已完成。
