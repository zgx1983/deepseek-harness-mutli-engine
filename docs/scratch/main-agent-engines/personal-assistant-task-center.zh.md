## 概述与范围

状态：设计完成，待实现。日期：2026-10-05。本文定义个人助理右侧工作台、父子任务详情、完整任务列表、历史检索和分页的拟议行为；不是当前功能说明。保留中栏完整对话、共享右侧栏、固定 Native 协调会话和固定工作目录。实现状态统一记录在[功能清单](../../../worktree-feature-list.md)。

用户进入助理页即可判断需要自己处理的事项、助理正在执行的任务、后续待办以及最近成果。一个任务可以拥有多个子任务，每个子任务可多次执行；用户可以从摘要进入完整详情，也能分页检索全部和历史任务。

本期包含两级父子任务、同一父任务内的依赖、任务验收、执行记录、成果引用、搜索筛选和服务端分页。不包含无限嵌套、跨父任务依赖、自动日程、截止提醒、重复任务、Agent Team 数据合并、产物全文检索或新的引擎选择能力。这些能力不能通过界面占位宣称已支持。

## 当前实现与差距

本文记录 2026-10-05 的任务中心设计提案。插件现已改为项目和 token 用量看板，当前行为见[插件 README](../../../plugins/dsh-personal-assistant/README.zh.md)。提案中描述的任务中心实现及其存储代码均已移除。

持久记录是单层 tasks 表，状态为 pending、running、review、attention、done、cancelled，每个任务保存 runs。dashboard 的 workItems 是每个任务生成的单项投影，不是真正的子任务；重复执行记录也不是子任务。现有记录没有 parentId、依赖、独立任务完成时间、验收历史或结构化成果索引。不能直接从这些投影推断父子关系。

本设计增加业务数据和查询能力，不能仅通过 CSS 扩充布局或把现有 runs 改名实现。原有设计中的上下布局及 JSON 任务文件描述不作为本期实现依据；固定会话生命周期沿用当前 README。

## 页面结构与导航

共享右侧栏保持一个助理标签页，不新增平行侧栏。顶部固定标题、新建任务和更多菜单；其下为状态计数及“概览／全部任务／历史”三个视图。计数表示未结束的父任务数量，子任务问题数另行标注，避免重复计数；点击计数进入全部任务并应用对应筛选。

概览按“需要你处理 → 正在执行 → 接下来 → 最近成果”排列，底部可选显示最近执行动态。全部任务负责完整管理；历史默认显示 done、cancelled 父任务。任务详情在同一侧栏内替换列表，保留返回入口和来源视图。打开执行会话通过共享会话导航，返回助理页仍能恢复原详情。

工作目录移入“更多 → 助理信息”，保持只读。更多菜单还可提供刷新、全部展开和全部折叠；任务取消、停止和删除类操作不放在全局快捷按钮中。保留共享侧栏已有宽度、折叠和全屏能力。

## 概览与任务卡片

需要处理区优先列出失败、待验收及未选择执行项目的事项。每张卡显示父任务、具体子任务（如有）、原因摘要和一个主操作；同一父任务多项问题合并为一张卡并显示问题数，点击进入定位后的详情。失败项主操作为查看原因，待验收为查看结果，缺项目为选择项目。

正在执行卡显示父任务标题、项目、整体状态、子任务状态分布、本轮开始时间、耗时和最近可用摘要。完成比例明确标为“已验收子任务 x/y”，不等同 token 消耗或实际工作量。正在执行没有可靠阶段事件时只显示执行中，不推测分析、编码、测试阶段，不显示虚构百分比或预计剩余时间。

接下来区展示待办和被依赖阻塞的父任务，阻塞卡给出具体原因。父任务不是独立执行时，启动操作表示启动当前可执行子任务；不会把整个父任务再启动一个重复执行会话。最近成果显示结果摘要、验收状态、完成时间和可靠的产物／执行会话引用。

概览各组默认最多展示 3 张父任务卡，数量由展示配置控制；更多通过查看全部进入对应筛选列表。空组不占大块空间。首次无任务展示新建任务和可粘贴的请求示例；清空筛选与新建任务使用不同空态。

## 父子任务与执行模型

本期固定两级：顶层任务为父任务，有子任务时父任务是汇总容器；没有子任务时父任务是可执行叶任务。子任务不能再创建子任务，不能属于多个父任务，也不能移动到另一个父任务。模型拆解任务时通过一次原子计划提交创建父任务、所有子任务及依赖，使等待中的后续任务一开始就可见。

子任务继承父任务项目，本期不提供每个子任务不同项目的执行。创建计划可以暂不指定项目，但启动前必须由 Host 确认项目。已执行任务的项目不可原地更改；需要更换项目时创建新任务，保留旧会话工作目录和身份。

叶任务可以多次执行，每次新增 Execution 记录并创建独立 Session。子任务生命周期和一次 Execution 生命周期分开：Execution ended 表示本轮结束，任务 review 表示等待验收，任务 done 表示已接受结果。stopped 或 failed 都不能当作完成。

已有叶任务可以在没有活动执行时转为父任务容器；原 runs 保留为拆解前历史，不自动归属新子任务，不参与新子任务汇总。转换记录到任务活动历史。顶层容器和它的子任务只在顶层列表计为一个任务，详情里单独计算子任务。

## 状态、依赖与验收

保留六种业务状态，增加独立的 availability（ready、blocked、needs-project）及 blockedBy。依赖阻塞是可执行性，不新增到持久任务状态枚举；UI 可以显示“等待依赖”。只有叶任务可被执行。每个子任务可声明同父任务内的 dependsOn，禁止自依赖、重复边、跨父任务引用和环。

默认依赖满足条件为前置子任务 done，即结果已经验收。review 不自动解锁后继；取消或失败也不满足依赖。若以后支持“执行成功即解锁”，须增加明确策略，不能改变默认语义。完成验收后 Host 重新计算可执行性；默认不自动启动后继，用户或协调模型显式启动就绪任务。自动连续执行属于后续可配置能力。

| 父任务状态 | 汇总规则（按顺序判断） |
|---|---|
| cancelled | 父任务取消已完成，且没有活动执行 |
| attention | 任一必要子任务失败，或必要前置被取消导致无法继续；即使别的子任务运行也显示问题及运行数量 |
| running | 没有上述问题，且至少一个子任务 queued/running |
| review | 没有活动执行，所有必要子任务均已 done，optional 项均已结束，但父任务尚未整体验收 |
| pending | 其他情况，包括子任务待办、等待依赖或尚有子任务 review |
| done | 必要子任务均已 done，父任务经过显式整体验收 |

父任务的“需处理／待验收”徽章独立于主状态，允许 pending 父任务标出待验收子任务。子任务完成率以 done 数除以全部子任务数，取消项单独计数。若需要放弃某个子任务，用户显式将其标为 optional；默认 required=true。required 集合不能为空；不以全部取消冒充整体完成。父任务验收前所有 optional 子任务也必须结束（done 或 cancelled），未完成的 optional 项通过明确的取消操作结束，不能留在已完成父任务下继续运行。

必要子任务均完成后仍需验收父任务成果。重新打开已完成子任务会撤销父任务完成状态和当前整体验收有效性，保留旧验收历史，并使依赖该子任务的后继重新计算阻塞。已有后继结果不删除；活动后继必须先停止或明确结束后才能重新打开其前置，防止执行中依赖变化。

取消父任务先阻止新执行，向所有活动子执行请求停止；确认停止后将未结束子任务及父任务标为取消，已完成子任务保留。停止失败时保持待处理并提供重试，不直接显示全部取消。删除、变更依赖和拆解在相关执行活动期间被 Host 拒绝。

## 任务详情与操作

详情采用“概况 → 需要处理 → 子任务 → 成果 → 执行历史”顺序。概况包含标题、目标、项目、当前状态、创建／更新时间、首次真实执行开始时间、本次完成时间与验收时间；缺少真实时间显示未开始／未完成，不根据 updatedAt 伪造起止时间。未知结束时间明确标为未知。

子任务行默认显示顺序、标题、状态、依赖提示、最近执行起止时间和耗时。展开显示完整描述、required 属性、前置引用、错误、本轮摘要、成果和操作。支持按状态筛选及“全部展开／折叠”；初始加载 20 项，加载更多保持顺序和已展开状态。没有子任务的任务详情直接显示自己的执行与成果。

```text
← 返回全部任务                  编辑  ⋯
整理并发布项目文档 · 项目 A
已验收子任务 2/5 · 1 项失败
概况／描述
需要处理：链接校验失败 → 查看原因
子任务                         [全部状态 ▾]
✓ 1 整理需求                   已验收
✓ 2 生成接口文档               已验收
● 3 补充使用示例               执行中
○ 4 汇总文档                   等待任务 3 验收
! 5 校验链接                   执行失败
                 加载更多
成果                           展开
执行历史                       展开
```

每个状态只显示合法操作；启动前显示未满足条件。结果验收的主操作为查看结果，接受结果在结果详情中明确提供。重试创建新的 Execution，不覆盖旧失败记录。针对任务提问将父任务和子任务 ID 可见地放入草稿，用户发送后才调用模型；UI 不静默发送消息。

停止和取消显示不同文案与效果；取消父任务明确提示受影响子任务数量。单个操作失败保留任务内容并用共享 Toast 提示，字段校验留在表单，长期查询失败显示紧凑重试提示。输入表单和未发送草稿在轮询期间不被重置。

## 完整列表、历史与搜索

全部任务默认显示所有未结束父任务，可以选择全部状态查看结束项；历史默认只显示 done、cancelled 父任务。两者复用同一查询和列表组件，但分别保存筛选条件及页码。子任务不作为独立顶层卡混入列表。

列表支持关键词、项目、父任务状态、子任务状态、创建时间范围、完成时间范围和排序。关键词第一版搜索父／子任务标题与描述，以及 ID 精确匹配；不搜索模型对话全文、错误堆栈或产物正文。子任务命中返回父任务及至多 3 个命中子任务摘要，点击定位对应子任务，父任务只出现一次。

默认按 createdAt 降序及 ID 固定排序；可以选择更新时间、完成时间和标题排序，所有排序均用 ID 作为最终次序。日期选择采用客户端时区的日界限，发送 UTC 的包含起点、不包含终点区间；未结束任务没有 completedAt，不匹配完成日期筛选。

历史页展示任务结束状态、子任务摘要、完成／取消时间、最近成果和原项目名称。项目删除时显示保留的项目名称及“项目不可用”；查看历史仍可进行，重新执行须选择有效新任务项目。历史属于同一持久任务集合的查询视图，不复制到另一个任务数据库；保留失败、重试、验收和取消记录。

清空搜索、切换页大小或改变筛选时回到第一页；详情返回恢复来源视图、筛选、页码和滚动位置。历史查询范围是全部持久任务，不限于当前页或前端已加载项。

## 分页与并发一致性

父任务列表采用服务端页码分页：默认 20 项，可选 50 项，最大值为经 Config 校验的限制。页脚显示总数、当前页／总页数、上一页、下一页及跳页输入；零结果显示 0 项，不产生第 0 页。详情中的子任务和执行历史各自分页，不嵌入根列表响应。

首次查询返回 queryId、queryRevision、totalCount、pageSize、pageCount、expiresAt 和当前页 items。Host 为规范化筛选保存短期查询快照，冻结父任务 ID 的集合与排序；后续翻页携带 queryId，避免新任务或更新导致重复、漏项及页码跳动。快照不复制完整描述、runs 或对话，只缓存紧凑 ID／排序记录；配额、有效期、最大结果量均通过 Config 配置。

| 拟议 Config 字段 | 初始默认值 | 校验／用途 |
|---|---|---|
| defaultPageSize / maxPageSize | 20 / 50 | 正整数，默认值不能超过上限 |
| overviewGroupLimit | 3 | 正整数，限制各组卡片 |
| querySnapshotTtlMs | 300000 | 正整数，限制快照生存期 |
| maxQuerySnapshotsPerIdentity | 16 | 正整数，限制每身份快照数量 |
| maxQueryResultIds | 50000 | 正整数，超过时要求收窄查询，不静默截断 |
| maxSummaryCharacters | 500 | 正整数，只限制摘要，不裁剪 ID 或状态字段 |
| searchDebounceMs | 250 | 非负整数，经配置接口传给客户端 |

默认值是拟议起点，配置均需 schema 校验；内存总配额也须受 Host 配置限制，超限返回明确错误。复用现有 pollIntervalMs，不新建另一套刷新间隔。

同一快照内的页摘要读取最新记录；因此状态可能与首次筛选不再一致，响应必须标出 changedSinceQuery，界面显示“有更新，刷新列表”而不静默删除当前行。新增任务不插入旧快照，刷新后才纳入。总数表示快照命中数，不是实时总数。详情读取最新数据并独立进行版本校验。

子任务、执行历史及活动列表沿用同样的查询快照语义，各自持有 queryId；加载更多不能把不同时刻的排序结果直接拼接。

queryId 过期、被回收或 Host 重启时返回 query-expired，保留当前内容和筛选并提供刷新；刷新建立新快照，尽量保留页码，超出页数则定位最后有效页并提示。queryId 绑定当前认证用户、Host 存储和规范化查询，不能跨身份使用；客户端不能用同一 queryId 修改过滤条件。

响应大小受限；快照配额耗尽或结果量超过配置时给出可恢复错误，建议收窄筛选，不悄悄截断总数。分页只减少响应和界面负担，不等同当前 domain 的启动内存已降低；现有 domain 有内存快照，数据规模优化需要另外验证查询设施。

## 数据结构与持久记录

以下为拟议字段，不是已经存在的接口。任务 ID、Execution ID 和跨包引用采用项目要求的 branded 类型；JSON 和持久读取处校验格式。Task、Execution 和 Activity 使用独立记录，父任务汇总由 Host 根据权威记录计算，不能依赖客户端或模型回复。

| 记录 | 主要字段与语义 |
|---|---|
| Task | id、parentId（顶层为空）、title、description、workspaceId、projectTitleSnapshot、order、required、dependsOn、status、revision、createdAt、updatedAt、startedAt、completedAt、cancelledAt、acceptedAt、acceptedBy |
| Execution | id、taskId、attempt、sessionId、status、ownerPid、startedAt、endedAt、summary、error；允许真实结束时间未知 |
| ResultReference | id、taskId、executionId、kind、title、summary、locator、createdAt；locator 为校验过的会话／产物引用，不接受任意可执行链接 |
| TaskActivity | id、taskId、rootTaskId、sequence、type、actor、occurredAt、executionId、相关状态／字段变化；记录创建、拆解、执行、停止、验收、重开及取消 |
| ParentSummary | root ID、主状态、子任务计数、待处理／待验收计数、availability、最近执行摘要及最近结果引用；可重建查询投影 |

任务与执行时间分别保存；父容器 startedAt 来自首次真实子执行，completedAt 为当前整体验收完成时间，cancelledAt 单独保存。重新打开后清除当前完成时间，旧完成与验收信息保留在 Activity。叶任务执行结束时间留在 Execution，验收时间留在 Task，二者不能混用。

本期无硬删除：取消与历史保留满足用户管理需求，避免查询快照引用消失。未来增加删除时须定义快照墓碑、引用及会话保留语义。成果引用仅展示已持久并校验过的结果，模型文字“文件已生成”不能自动创建文件引用。

## 查询与操作接口

保持现有认证 POST `/api/personal-assistant/tasks` 操作入口，新增以下拟议 op；实现时同时更新 Host、模型工具和客户端响应验证。固定协调会话 ensure／recover 操作保留原有语义，dashboardSnapshot 在消费者迁移完成前保留，不再用作任务页完整数据源。

| 拟议 op | 请求要点 | 响应／行为 |
|---|---|---|
| overview | 项目筛选、各组限额 | 父任务计数、有限摘要、执行动态、数据 revision |
| listTasks | view、filters、sort、page、pageSize；翻页可携带 queryId | 分页摘要、命中子任务摘要及查询元数据 |
| getTask | taskId | 最新概况、汇总及合法操作，不携带完整执行历史 |
| listChildren | parentId、状态筛选、分页信息 | 有序子任务摘要及总数 |
| listExecutions / listActivity / listResults | taskId、范围（当前节点或整棵任务）、分页信息 | 分页记录，稳定 ID 和真实时间 |
| createPlan | parent、children、dependsOn、requestId | 原子创建计划及完整 ID 映射，依赖失败时全量拒绝 |
| updateTask / updatePlan | expectedRevision、字段变更、requestId | 校验后的新记录和汇总；版本冲突不覆盖 |
| startTask / startReadyChildren | ID、expectedRevision、requestId | 本次新增执行引用及未启动原因；遵循现有执行调度限制 |
| acceptTask / reopenTask / stopTask / cancelTask | ID、expectedRevision、requestId | 状态及活动记录；父取消允许返回 stopping 中间操作状态 |

所有写操作检查权限、引用、合法状态和 expectedRevision；requestId 去重防止网络重试重复创建任务／执行。重复请求返回原操作结果；不同请求内容复用同一 requestId 被拒绝。修订冲突返回 revision-conflict，保留编辑草稿并提示重新加载，不隐式覆盖。

模型工具可创建计划、查询分页任务、查看详情及请求执行；验收由用户操作，模型不能自行把 review 标为 done。任务筛选不得擅自跨身份或绕过当前存储。模型选择子任务时使用真实 ID；新模型可见的任务信息及工具结果需要进入可重建的 Session 记录和快照。

这些名称是设计约定，实施时可统一调整，但必须同步全部消费者与文档；不能让客户端先依赖尚未实现的 op。

## 存储查询与迁移

Task／Execution／Activity 持久写入继续通过 storage-domain；不让插件绕过 domain 内存快照直接修改 SQLite 文件。现有 domain 接口未证明支持索引查询和跨表事务，因此这两项是实施前必须完成的能力确认，不把 SQLite 后端的存在等同业务查询接口可用。

首版 Host 可在已有 domain 快照上构建仅包含查询字段的派生索引并进行服务端分页；每次持久写入成功后增量更新索引。读模型可完全重建，不新增第二份权威任务存储。此方式不会消除启动时加载全部 domain 记录的内存成本，必须用目标任务规模验证。若测量不达标，在同一迭代中补齐 storage 的查询服务定义、后端提供者及消费者，不能直接对私有 SQLite schema 编写旁路 SQL。

createPlan 和涉及多条任务的状态变更采用跨记录事务，任务、执行引用及活动记录一次提交；若现有 domain 不支持，须在同一迭代先补齐事务服务定义、SQLite 提供者、domain 消费者和持久完成后的内存发布。事务失败时不发布部分内存状态，重启后不出现半个计划。多个逐条写入加“失败后尽量回滚”不满足本设计。

启动外部 Session 不能包含在数据库事务里。先持久登记带 requestId 的执行意图并领取启动权，再创建／启动 Session，最后持久确认 sessionId；中间崩溃进入启动待确认，不能自动重试生成第二个 Session。恢复时按已保存身份与实际会话核对，无法确定则进入需要处理；取消与启动通过同一任务修订及领取状态协调。

迁移保留所有现有任务 ID、状态、项目、runs 和协调会话 singleton；旧任务成为无子任务的顶层叶任务，旧 runs 映射为执行记录。没有真实验收／完成时间的旧任务保持未知，不从 updatedAt 填入假时间。迁移活动仅记录迁移发生，不补造旧状态历史。

按 domain 版本机制和项目持久类型规则设计相邻迁移、幂等校验、失败恢复及升级指南；SQLite schema 版本单调增加。原版本记录和已发布迁移不覆写；明确旧构建不支持读取新数据，不声称可降级。迁移前停止该存储的 Host 并备份任务与会话数据，迁移失败不得清空数据库；会话日志不改写。

同时更新 [持久类型评审要求](../../cookbook/reviewing-persistence-type-changes.zh.md)中的确认材料；本期仅设计，不修改 domain schema、不生成真实迁移。

## 刷新、响应式与可访问性

只轮询当前可见视图的摘要或详情，沿用 pollIntervalMs；不可见时暂停，重新激活刷新。筛选搜索防抖并取消旧请求，协调会话更换、视图切换或 queryId 更换后拒绝过期响应。首次加载使用共享骨架，刷新保留旧内容；后台轮询不反复显示成功 Toast。

视图状态（筛选、页大小、当前任务、展开项、滚动位置）按助理存储身份保存为本地展示偏好，不把过期 queryId 当持久业务数据。不同 DSH_HOME 不混用偏好。列表出现更新时显示轻量刷新提示，不抢焦点、不展开用户收起的区块、不跳页；编辑中的任务变更只提示版本冲突。

窄侧栏使用单列卡片，项目／时间换行；宽侧栏增加摘要与时间列，详情可采用信息网格。布局以容器宽度适配，不使用全窗口宽度推断侧栏宽度。页码操作可换成两行，标题及返回入口始终可见。面板仅保留一个主滚动区，长文本和历史使用按需展开，不制造多层常驻滚动条。

复用共享 Tabs、Button、Tooltip、Toast、菜单、滚动样式、主题颜色和字体变量，新增字重不超过 500。状态同时用文字和图标表示，不能只靠颜色或呼吸动画；减少动态效果偏好下关闭脉冲。折叠按钮具备 aria-expanded，分页可键盘操作，进入／退出详情恢复合理焦点，中英文和明暗主题均验收。

请求 404 保留当前 profile 未加载助理的明确错误及恢复入口；授权／网络问题不替换协调会话、不重置任务。列表和详情刷新失败保留最后成功数据并标记更新时间；局部操作失败不遮住整个面板。

## 实施顺序与文件归属

先完成数据与原子写入设计及迁移，再交付查询、父子生命周期和模型工具，最后实现右侧 UI；每阶段均保持 Host／Client 消费者一致。阶段 1：存储能力确认、Task／Execution／Activity、迁移和状态规则；阶段 2：原子 createPlan、依赖与验收、幂等及并发检查；阶段 3：查询快照、分页、历史与索引；阶段 4：概览、详情、列表、历史及会话联动；阶段 5：规模测试、双端真机验收和迁移材料。

| 归属 | 主要工作 |
|---|---|
| 插件 storage.js | 新版持久记录、写入单元和迁移接入 |
| 插件 runtime.js | 父子生命周期、依赖验证、原子计划、验收、查询与模型工具 |
| 插件 index.js / api.js | 认证操作分派、错误码、分页响应校验和请求取消 |
| 插件 client.jsx | Overview、TaskList、TaskDetail、ChildList、HistoryList 和视图状态；避免继续膨胀单个 TaskPanel |
| 插件 css.js / locales.js | 共享样式复用与完整双语文案 |
| storage 服务（仅缺能力时） | 完整的事务／查询服务定义、提供者、消费者及文档 |
| 插件 README、功能清单及升级指南 | 发布行为、迁移步骤和逐项验证状态 |

实现期间更新现有条目，不把设计通过写成实现完成。既有固定工作目录、唯一协调会话、历史恢复、项目执行和共享侧栏注册仍须回归。不得以阶段 4 视觉上线代替父子任务与分页的完整交付。

## 验收矩阵与性能目标

| 验收场景 | 预期结果 |
|---|---|
| 一个父任务、三个有顺序依赖的子任务 | 创建后全部可见；前置未验收时后继显示依赖及阻塞原因 |
| 必要子任务失败，同时另一个运行 | 父任务显示需处理，同时保留运行数量及会话入口 |
| 叶任务重试三次 | 仍为一个子任务，执行历史保留三轮及真实起止时间 |
| 子任务全部验收、父任务尚未验收 | 父任务 review，用户整体验收后才 done |
| 取消、停止失败、重开已验收前置 | 不伪装完成；依赖和验收有效性按规则更新 |
| 非法依赖、自环、跨父引用、修订冲突 | Host 拒绝，无部分计划、丢失修改或重复执行 |
| 20 项分页下有 21／40／41 个父任务 | 页数和边界正确，无重复计入子任务 |
| 同一快照翻页期间新增或修改任务 | 成员及顺序稳定；变化提示可刷新，不自动跳页 |
| queryId 过期／Host 重启／身份切换 | 明确拒绝，保留筛选并重新查询，不能跨身份读取 |
| 搜索只命中未加载页的子任务 | 返回唯一父任务、命中摘要并定位详情 |
| 历史日期筛选、项目删除、旧任务迁移 | 全量范围正确，真实时间未知可辨，旧记录完整 |
| 查询失败、重复点击、页面切换、恢复会话 | 保留内容，幂等写入，拒绝旧响应，草稿和身份不丢失 |
| 窄栏／宽栏、键盘、中英文、明暗主题 | 控制可达，布局无溢出，焦点和折叠状态正确 |

性能验收数据建议包含 10,000 个父任务、每个 5 个子任务、每个子任务 3 次执行，另覆盖单父任务 1,000 个子任务。固定测试机、数据生成种子和冷／热查询条件后测量；目标而非当前承诺：热查询第一页 p95 ≤ 300 ms，子任务展开 p95 ≤ 200 ms，常规 20 项摘要响应 ≤ 128 KiB，侧栏同时渲染的根列表节点受当前页约束。超长摘要按响应字段上限截断并提供详情，不裁掉必要状态。

测量冷启动内存、索引构建、关键词检索和快照配额；当前 domain 的内存加载可能成为瓶颈，超标时不能只增加服务端分页来宣称解决。性能阈值由可复现基线最终确认，持续记录实际结果。

测试覆盖 Host 生命周期与查询、迁移、客户端分页／焦点／错误状态、模型工具 keyless Session 快照，以及 Web／Desktop 真机流程。实现完成后用 `pnpm run build:local` 协调构建依赖、插件和双端产物；构建输出按[本地构建文档](../../cookbook/local-builds.zh.md)保存，编译通过不代替功能验收。

## 开发备注与实施前决策

日程、优先级、截止时间、重复任务、跨项目子任务和依赖流程图可单独扩展；不在本期验收中占用虚构数据。若需要改变本期规则，先更新本设计与功能清单，再同步实现和验证。
