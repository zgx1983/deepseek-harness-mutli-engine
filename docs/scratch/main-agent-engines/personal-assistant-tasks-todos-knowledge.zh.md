# 个人助理任务、Todo 与长期知识设计

[English](personal-assistant-tasks-todos-knowledge.md) | 中文

## 摘要

个人助理通过完整对话框管理任务执行、记录 Todo 和保存个人想法。右侧工作台提供任务、Todo、知识三个入口。任务与 Todo 使用个人助理专属的结构化持久化存储，独立于 Agent Team 和会话日志；个人知识以 Markdown 文件为权威正文。任务的每次执行关联独立会话，用户可以从任务进入对应会话、查看过程、报告进展并确认成果。

## 范围与当前状态

本方案确认于 2026-10-07，描述拟议功能与交互，不代表后端已经实现。当前插件已有固定 Native 协调会话、固定工作目录、父子任务、依赖、项目关联、执行记录和验收机制；任务启动尚未明确传入引擎与模型，执行会话入口仍以只读记录展示。Todo、长期 Markdown 知识及执行会话内的任务工具需要新增。实际实现状态以[功能清单](../../../worktree-feature-list.md)和[插件 README](../../../plugins/dsh-personal-assistant/README.zh.md)为准。

本期包含任务执行配置、会话导航、进展及成果回传、用户验收、Todo 转任务和长期知识的保存与检索。不限于 Agent Team 运行期，也不要求主助理会话一直保持原始上下文。全文语义检索、自动提醒、自动周报、无限层级任务和完整文件编辑器不作为首版交付要求。

<a id="layout"></a>
## 页面布局与原型

保持左侧导航、中栏完整对话框及共享右侧栏。中栏不增加“当前关注”或任务摘要条。右侧顶部为个人助理标题和随当前页变化的新增按钮，下方为“任务 / Todo / 知识”三个入口；任务数量表示未结束父任务，Todo 数量表示未完成项，知识数量表示有效文档。

[打开 HTML 交互原型](personal-assistant-sidebar-prototype.html)。原型为独立文件，无外部运行依赖；可直接在浏览器中打开。顶部支持 320–560 px 栏宽调整、浅／深色切换及示例重置。全部数据和操作仅用于当前页面演示，刷新后重置；Markdown 下载生成的是示例内容。脚本语法与渲染 smoke 已检查，真实浏览器的视觉验收仍需进行。

```text
个人助理                     ＋ 新建
[任务] [Todo] [知识]

任务：概览 / 全部任务 / 历史
      正在运行 → 等待确认 → 待办 → 历史
Todo：未完成 / 全部 / 已完成、已转任务
知识：全部 / 想法 / 笔记
```

列表、详情、筛选和分页均在同一右侧栏内切换。各入口独立保留条件、页码和滚动位置；进入详情后返回恢复来源列表。任务组可以折叠，展示完整数量及有限条目，超出后提供完整列表入口。搜索和长列表采用分页，不能把全量历史塞进概览。窄窗口可由共享框架切换侧栏呈现方式，原型在窄屏只展示工作台以便评审。

“针对这项提问”将带稳定引用的内容放入对话草稿，由用户发送；界面不静默发送消息。所有任务状态同时使用文字和视觉标记，失败、依赖阻塞与缺配置不能仅用颜色表示。主题、键盘、焦点和共享侧栏规范沿用现有客户端组件。

<a id="tasks"></a>
## 任务创建与执行配置

用户可通过助理对话或右侧表单创建任务，指定项目、引擎、厂商和模型。例如：“在 harness 项目里创建任务，用 Claude 和 DeepSeek Flash 检查权限配置，完成后提交修复说明。”任务保存标题、目标、验收条件、项目、执行配置、父子关系、依赖及来源引用；来源可为对话、Todo 或知识文档。

“创建任务”只保存待执行任务；“创建并开始执行”在创建后检查条件并启动。保存允许项目或执行配置未完整，展示具体缺项；启动要求全部必需项已解析、项目可用、依赖满足、引擎可用且模型配置兼容。父任务为容器时只启动就绪子任务，不额外创建父任务执行会话。

向协调模型提供真实的项目、引擎、厂商和模型目录，由模型理解用户简称并选择准确标识；Host 验证标识存在、引用有效和引擎兼容性，不以本地模糊匹配擅自替换选择。有多个合理候选时，助理向用户展示候选并澄清。未指定时使用可配置的个人默认设置，并在启动前明确展示。失败应指出缺项或不兼容原因，不退回另一个模型。

父任务提供默认执行配置，子任务可以显式覆盖引擎、厂商和模型；首版项目归属沿用同一父任务下的既有规则。每次执行保存实际采用的配置快照。修改任务默认配置只影响后续执行，已创建会话及历史快照不变；更换已经执行任务的项目遵循既有项目锁定规则。

<a id="sessions"></a>
## 执行会话与状态回传

每次执行尝试关联确切的 Session，并持久保存任务、Execution 与 Session 的关联。运行中任务卡提供“进入会话”，结束后进入最近一次；多次执行可在详情中按尝试进入。父任务卡进入当前活动子任务会话，有多个活动子任务时提供明确选择；每个子任务也有独立入口。尚未执行显示“未创建会话”，会话不可用时保留执行记录并解释原因。

执行会话在第一次模型请求前获得明确的所属上下文：项目标识、项目名称、实际工作目录、任务标识、目标、验收条件、当前状态、父任务与依赖，以及本次 Execution 标识和实际执行配置。Host 从持久关联生成这些信息，不能只在启动提示中写入一段文字后依靠模型记忆。会话重新打开、进程重启或上下文压缩后，可通过任务查询工具重新获得最新状态；提供给模型的上下文和查询结果进入可重建的 Session 记录。

执行详情显示引擎、厂商、模型、开始及结束时间、状态、进展、成果和失败原因。未知时间不补造。父任务详情汇总子任务依赖及状态，执行记录标明所属子任务，避免把子任务尝试误认为父任务单独执行。

进入执行会话使用共享会话导航，不嵌套另一套聊天组件。会话提供关联任务信息、任务详情入口及“返回个人助理”；返回恢复原任务详情、来源视图与滚动位置，保留助理草稿。会话导航本身不启动任务或发送消息。

执行模型可查询关联任务、报告进展、说明阻塞和提交成果。Native 使用框架工具；Claude 和 Codex 通过各自支持的工具或 MCP 接入获得相同操作。Host 根据可信的 Session–Execution 关联限定工具范围，不能仅相信模型传入的 taskId、executionId 或 actor。历史执行会话可查看记录，过期尝试不能继续修改当前执行状态；重新执行产生新的 Execution 和会话，不覆盖旧记录。

```text
待执行 → 执行中 → 等待确认 → 已完成
             ↘ 需要处理 → 重试
```

模型明确提交成果后任务进入等待确认；一轮回复结束、进程正常退出或文字声称完成都不能单独证明业务任务完成。失败、停止和恢复仍走现有生命周期规则。成果保存摘要及 Host 校验过的会话或产物引用；用户可先进入会话查看完整过程。

用户可以在右侧点击确认，也可以在助理或执行会话中明确要求验收完成。对话确认通过可信用户操作路径绑定具体任务、执行和修订版本，不能由模型写入 actor=user 来伪装授权。任务有歧义时先定位；确认时重查状态和版本。子任务确认后由 Host 重新计算依赖与父任务汇总；有未完成必要子任务时不能完成父任务，也不默认自动启动后继。

用户在当前执行会话中明确说“这个任务完成了”或“验收通过，标记完成”，表示对该会话绑定任务的完成指令，无须再次输入任务 ID。模型理解意图并请求完成操作，Host 从当前可信会话关联定位任务与执行，核对原始用户消息、状态和修订版本后持久写入 done、完成时间、验收时间及用户操作记录，再返回具体任务名称和更新结果。普通讨论、引用文字、条件表达或模型自己的完成声明不作为用户验收。重复完成请求返回已有完成结果，不重复生成验收记录；无法定位、版本冲突或不满足条件时明确解释，不回复已完成。

用户明确验收可完成当前执行任务，不要求模型先报告完成；如果执行仍在运行，必须先在受控执行结束位置停止或收敛该执行，确认其不再运行后再完成任务，停止失败不能标记 done。当前会话属于子任务时，完成操作只更新该子任务，父任务由 Host 汇总；未完成必要子任务阻止父任务完成。旧尝试关联已被新执行取代时，旧会话只可查询并引导进入当前会话，不能应用完成指令到新尝试。

状态修改写入同一份任务存储，右侧与各会话共享权威记录。客户端通过刷新或订阅同步投影，不从聊天文本另建任务状态。

<a id="todos"></a>
## Todo 与任务转换

Todo 保存尚未准备执行的行动意向，不要求立即配置项目、引擎、模型或验收条件。用户可通过对话说“记个 Todo，下周整理权限映射文档”，或使用右侧新增。记录内容、补充说明、标签、优先级、可选日期、来源对话、知识引用和关联任务。

Todo 提供未完成、全部以及已完成／已转任务视图，支持新增、编辑、搜索、分页、勾选完成和恢复未完成。状态为未完成、已完成、已转任务、已取消；转为任务不代表工作已完成。日期用于展示、排序与筛选，未接入提醒时不宣称会主动通知。

每条未完成 Todo 提供“转为任务”，也支持助理对话转换。转换补充项目、目标和执行配置，可保存待执行或明确创建并启动。任务创建、Todo 状态修改和关联写入在同一事务中完成；重复点击或请求重试返回同一个转换结果。保留 Todo 原文、来源和历史，显示关联任务入口及当前状态。

支持多条 Todo 合并为一个任务，保留每条来源关联。首版单条 Todo 默认只转换一次；再次拆解或创建任务需明确操作，不把重复请求当成新的计划。关联任务取消时由用户决定是否恢复 Todo，不自动恢复、删除或抹去关联历史。

<a id="knowledge"></a>
## 个人想法与 Markdown 知识

右侧“知识”区分想法和笔记：想法可以零散，笔记承载整理后的经验与结论。用户明确要求记录或保存时持久写入；任务执行中模型提炼的经验先作为保存建议，不自动覆盖知识。

默认知识目录为 `$DSH_HOME/personal-assistant/knowledge`，允许配置为其他目录。想法放在 ideas，整理笔记放在 notes；模型和其他工具可以直接搜索、读取这些 Markdown 文件。

```text
knowledge/
├── ideas/
│   └── 2026-10-07-weekly-summary.md
└── notes/
    └── permission-mapping.md
```

每篇文档有稳定 ID、标题、创建与更新时间、标签、项目及任务／Todo 引用，正文保留原始表达和后续整理。文件路径可变化，关联使用稳定 ID。frontmatter 缺项、重复 ID 或格式错误应明确报告，不静默丢弃内容；外部新增文件可通过显式导入或修复补齐元数据。

```markdown
---
id: idea-稳定标识
title: 个人助理每周总结
created: 2026-10-07
updated: 2026-10-07
tags: [个人助理, 周报]
projects: []
relatedTodos: []
relatedTasks: []
---

# 个人助理每周总结

## 原始想法

根据本周任务执行情况，整理完成事项、未完成原因和下周计划。

## 补充与整理

后续补充的内容，以及确认保留的整理结果。
```

知识视图支持标题、正文、标签和项目搜索，查看正文及 Markdown 源文，并提供新增、补充、下载、生成 Todo、创建任务和在对话中讨论。更新时先明确目标记录，有多个候选时列出供用户选择。模型整理保留用户原文，修订保留版本备份；不默默合并相似想法。

Markdown 是唯一权威正文，搜索索引和右侧摘要可以缓存，但必须能从文件重建。用户直接编辑文件后，客户端和检索识别修改；写入检查文件版本，冲突时重新读取并处理，避免覆盖外部编辑。知识读取及写入限定在配置目录，拒绝路径穿越和逃逸目录的链接。

长期保存不意味着每次加载全部知识。首版使用文本、标签及项目检索，按问题取少量相关记录，回答附带可打开的知识引用；语义索引可在后续加入。检索内容作为参考资料而非系统指令，模型可见的正文及检索结果须能从 Session 记录重建，不能只记录随时变化的文件路径。

知识可生成 Todo 或任务，创建后保留文档关联。结构化存储与文件系统之间没有同一数据库事务：跨介质关联需用持久操作意图、幂等重试和恢复核对完成，失败时保留原文件并显示未完成关联，避免声称已经原子写入两处。

<a id="storage"></a>
## 持久化与一致性

任务和 Todo 属于个人助理专属存储，不复用 Agent Team 任务板，不依靠协调会话恢复业务数据。可以共用个人助理 SQLite 数据库，但使用独立表和访问接口，使 Todo 转任务能够保持数据库事务。任务表、执行表、成果表、活动表及 Todo 表分别拥有明确记录；知识只在数据库保留可重建索引和关联，不复制权威正文。

任务及 Todo 写入携带修订版本与请求去重标识，冲突不覆盖其他客户端编辑；状态转换由 Host 验证，模型只请求操作。事务失败不发布半份计划，重复转换不创建第二个任务。开始执行先保存执行意图，创建会话后保存关联；崩溃后的未确认意图通过核对进入可恢复状态，不盲目重复创建 Session。

Markdown 写入采用同目录临时文件和原子替换，保存修订备份，管理重命名与稳定 ID 索引。多 Host 写入和用户外部修改需要版本检查与串行化机制，不能把客户端缓存当成权威数据。备份同时涵盖个人助理数据库、知识目录和所引用的会话日志。

助理会话压缩、恢复或更换不删除任务、Todo 或知识。执行会话不可用不删除任务记录，知识文件缺失不丢弃关联历史。新增持久字段遵循仓库声明、类型变更确认及迁移规则，已提交旧代数据保留，使用明确后继或受支持的单调 schema 迁移，不声称可降级。

<a id="interfaces"></a>
## 工具与接口职责

以下为拟议操作分组，并非当前接口清单。界面、协调模型和执行模型共用 Host 业务能力，但授予的范围不同。

| 使用方 | 能力 | 限制 |
|---|---|---|
| 助理协调会话 | 查询目录、创建与更新计划、请求执行、管理 Todo、检索与保存知识 | 不能代替用户验收；模型选择真实标识后仍由 Host 验证 |
| 当前执行会话 | 查询关联任务、报告进展、阻塞与成果 | 只限当前绑定执行；不能更新无关任务或过期尝试 |
| 用户界面与可信对话操作 | 配置任务、导航会话、确认成果、取消与恢复、编辑 Todo 和知识 | 状态、修订和身份检查一致，点击导航不触发执行 |
| 查询及同步服务 | 分页、搜索、详情、执行历史和变更投影 | 权威记录来自结构化存储或 Markdown，缓存可重建 |

模型工具输入、HTTP／RPC 输入、持久读取和文件元数据在对应外部入口校验。工具结果、任务上下文及检索知识按模型可见即有日志的规则记录。Claude／Codex 的工具传递、引擎准备就绪和首条任务消息提交沿用各引擎正式接入方式，启动失败不得留下看似已运行的任务。

<a id="acceptance"></a>
## 实施顺序与验收

第一阶段完成任务闭环：项目、引擎和模型配置，执行快照，会话导航，当前执行工具，进展及成果回传，以及用户在界面或对话中的验收。第二阶段增加 Todo 专属记录、右侧入口、转换与来源关联。第三阶段增加 Markdown 知识目录、修订、搜索、外部修改识别和按需检索。每阶段同时维护接口消费者、README、功能清单和适用的迁移文档，验证后再标记完成。

| 验收范围 | 必须观察的结果 |
|---|---|
| 配置解析 | 简称由模型结合真实目录选择；歧义可澄清；不存在或不兼容的配置拒绝启动 |
| 会话入口 | 当前、历史及子任务进入确切 Session；无会话与不可用情况明确；返回恢复助理视图 |
| 三种引擎 | Native、Claude、Codex 均能获得受限任务工具，启动与提交顺序正确 |
| 状态回传 | 回复结束不自动完成任务；成果进入等待确认；当前会话中用户说“任务完成”可更新绑定任务，原始消息与验收记录可追溯；重复请求幂等；过期执行不能改当前任务 |
| 所属上下文 | 首次模型请求前可知项目、工作目录、任务与执行身份；重启、重新打开和压缩后可查询最新状态；任务上下文可从 Session 日志重建 |
| 父子与依赖 | 必要子任务未结束时父任务不能完成；确认后依赖重新计算；无重复父任务执行会话 |
| Todo 转换 | 重试不重复创建；失败不留下半份关联；任务取消后的 Todo 恢复需用户选择 |
| Markdown | 原文、修订与稳定引用保留；外部编辑被识别；冲突不覆盖；索引重建后可检索 |
| 独立持久化 | 重启、更换助理会话和上下文压缩后数据仍存在；会话缺失不删除任务或知识 |
| 界面 | 三入口、搜索、分页、折叠与空状态可用；草稿及返回位置稳定；窄栏、双主题和键盘可操作 |

原型覆盖主要交互的示意，不代替真实 profile 的运行、跨客户端一致性、引擎接入、文件冲突和重启恢复验收。任务规模、搜索延迟与大量 Markdown 文件下的性能需要用实际数据单独测量。
