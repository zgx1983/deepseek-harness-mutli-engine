## 范围与设计关系

状态：中栏当前关注条设计已撤销；对话保留完整独立区域，右侧任务分区仍为当前设计。日期：2026-10-07。本文记录原始布局方案，不定义后端状态转换、调度、接口或存储迁移。

保留左侧导航、中栏对话、共享右侧栏。中栏增加紧凑“当前关注”；右侧默认按“正在运行 → 等待确认 → 待办任务 → 历史任务”组织，替代[任务工作台设计](personal-assistant-task-center.zh.md)中的默认概览组织。该文的父子任务、完整列表、历史检索和分页设计继续作为相关能力参考；本文不宣称这些能力在所有端已完成验收。

界面目标：让用户快速找到正在执行的工作、需要确认的结果与接下来要做的事，同时保持中栏对话和输入框可用。任务取消、失败及审批的实际语义仍以功能实现为准，UI 不通过标签改变业务状态。

## 中栏当前关注

对话上方增加一个紧凑区域，默认两三行：关注任务的标题和状态、最近可靠摘要、查看任务入口。默认内容区高度目标不超过中栏可用高度的 15%，普通窗口约 64–96 px；实际值实施时使用共享尺寸变量或可配置展示偏好。摘要最多两行，不能随内容无限增长，展开长文本到任务详情。

用户在右侧任务详情选择“关注此任务”后固定当前关注；查看其他详情不自动切换，轮询不改变关注。只允许同时关注一个父任务，可附带当前子任务提示。提供“取消关注”和收起；收起后只保留一行标题、状态及查看入口。关注任务结束后保留结果提示，用户可以查看或取消关注，不强制切换到另一个任务。

没有关注任务时显示简短数量摘要，例如“2 项执行中，3 项等待确认”，点击数量定位右侧相应分区；没有任何任务时显示简短新建入口。不开辟完整列表、日历或大面积统计图，不自动发起模型请求。

窗口较矮时优先使用单行形态。中栏对话占剩余空间，消息区独立滚动，输入框始终可见；不复制对话组件、不隐藏权限／中止等必要控件。收起及关注偏好按助理身份保存，跨不同助理存储不混用。

## 右侧信息顺序

| 顺序 | 分区 | 默认内容 | 主操作 |
|---|---|---|---|
| 1 | 正在运行 | 正在做什么、最近进展、子任务汇总、异常 | 查看进展 |
| 2 | 等待确认 | 结果摘要、结束时间、需要用户确认的事项 | 查看结果 |
| 3 | 待办任务 | 目标、是否可开始、依赖或缺配置原因 | 查看任务／开始 |
| 4 | 历史任务 | 已确认或已取消的任务入口 | 查看历史 |

顶部保持“我的任务”、新建和搜索入口。前三组使用一个主滚动区，分组可折叠、标题显示数量；保存用户折叠偏好。默认每组展示最多 3 项，提供查看全部及总数，限额作为展示配置而非硬编码业务规则。组内只列父任务，子任务在卡片汇总和详情中呈现。

执行结束但结果尚未确认时，在等待确认中突出展示；用户确认后才在历史中展示已确认结果。实际进入分区必须来自可靠的任务／结果记录，不能根据对话里“已完成”判断。

有活动子任务的父任务放正在运行；无活动执行但存在需确认结果的父任务放等待确认；其余未结束任务放待办。同一个父任务在默认视图只显示一次，其他关注事项通过卡片上的“待确认／需要处理”徽章呈现。当前父任务状态与该展示分区可不同，不伪造状态转换。

失败任务不被藏入历史：有活动执行时在运行卡突出失败，无活动执行时在待办顶部显示“需要处理”及原因。失败是否需用户确认或重试以真实操作能力为准；普通执行失败不显示“确认完成”。空组缩为紧凑标题或状态提示，不占大块留白。

## 线框示意

以下仅是视觉示意，不表示实际任务或已实现功能。

```text
中栏                                    右侧 · 我的任务     ＋任务 搜索
┌ 当前关注                    收起 ┐    正在运行 2                   ▾
│ 整理项目文档 · 执行中             │    ┌ 整理项目文档 · 执行中       ┐
│ 正在补充使用示例   [查看任务]     │    │ 子任务 2/5 · 1 项待确认     │
├──────────────────────────────────┤    │ 最近进展：补充使用示例      │
│                                  │    │ [查看进展]              ⋯   │
│             助理对话             │    └────────────────────────────┘
│                                  │    等待确认 3                   ▾
│                                  │    ┌ 检查配置兼容性              ┐
│                                  │    │ 发现 2 处需要调整的配置      │
│                                  │    │ [查看结果]                  │
│                                  │    └────────────────────────────┘
│                                  │    待办任务 6                   ▾
│                                  │      ○ 整理发布说明 · 可开始
├──────────────────────────────────┤      ○ 完整构建 · 等待文档任务
│ 输入消息……                       │                  查看全部 6 项 →
```

历史默认为入口，不在首页展开大量结束任务；执行动态留在任务详情中，避免增加第五个同级信息区。

## 卡片与状态详情

运行卡采用进展样式：标题、状态、当前子任务摘要、真实耗时和查看进展；没有可靠阶段数据时只显示执行中，不猜测步骤或百分比。等待确认采用结果样式：优先显示产出和确认事项，弱化执行过程。待办采用紧凑行：目标及阻塞原因，展开后再看完整计划。

点击卡片在同一右侧栏打开详情，不新增常驻第四栏。顶部提供“返回正在运行／等待确认／待办”，保留来源列表及滚动位置。“查看全部”进入完整列表并应用分区筛选；搜索和历史进入可分页的列表视图，返回恢复条件及页码，不在首页塞入全量内容。

| 类型 | 详情首要信息 | 后续信息 |
|---|---|---|
| 正在运行 | 当前进展、活动子任务、异常 | 完整子任务、成果、执行记录 |
| 等待确认 | 结果摘要、产物、确认事项 | 子任务结果、执行过程及历史 |
| 待办 | 目标、子任务计划、启动条件 | 描述、依赖及旧执行 |
| 历史 | 最终结果、用户确认情况 | 子任务及各次执行记录 |

父任务卡显示子任务状态汇总，详情用可折叠子任务行展示描述、依赖、错误、成果和执行记录。子任务很多时使用筛选及分页／加载更多，不无限展开。待确认结果以明确的父／子任务身份显示；子任务确认不暗示父任务已整体验收。

确认按钮放在结果详情，提供查看结果后确认的路径，避免列表误点。结果不可用或没有可靠摘要时明确显示暂无可查看结果，不生成假产物。停止、取消与重试放在任务详情或更多菜单，取消父任务提示影响范围。

## 交互、适配与反馈

中栏关注任务与右侧选中任务分别保存，彼此不自动替换；查看任务可打开侧栏并定位详情，关注此任务也不向对话发送消息。针对任务提问只粘贴可见任务引用到草稿，用户确认发送；输入和光标不被刷新夺走。

任务分区变化时不在用户正在操作的卡片上突然卸载内容。展示“状态已更新”的轻量提示，安全刷新或用户返回后再重排；新出现的待确认数量可以即时更新，但不抢焦点、不自动展开区块。返回详情恢复来源，已不匹配原分区的任务在详情明确显示最新状态。

窄栏卡片单列、元信息换行，宽栏可增加摘要和时间列；以侧栏容器宽度适配。中栏上方区域在矮窗口收成一行，右侧页脚换行保持操作可达。尽量使用一个主滚动区，避免卡片、分组、列表三层常驻滚动。

复用共享组件、主题与文字尺寸，新增字重不超过 500。状态使用文字和图标，不能只靠颜色。折叠按钮有 aria-expanded，菜单支持 Escape 与外部点击，返回详情恢复焦点；动画遵循减少动态效果设置。文案走双语字典，明暗主题均检查。

首次加载用共享骨架，刷新保留内容；网络错误提供局部重试，操作失败保留任务并使用共享 Toast。无任务、无筛选结果、无历史和结果暂不可用使用各自明确空态。

## 界面验收与范围约束

验收覆盖：普通与矮窗口下对话／输入框足够可用；关注区两三行封顶、单行收起、固定选择；右侧顺序及分区计数明确；父任务不重复列出；运行中的待确认或失败子任务可发现；结果查看与确认路径清楚；待办阻塞原因可见；历史检索分页不挤占首页；详情返回恢复位置；刷新不丢草稿、不抢焦点、不改变收起偏好。

在 Web／Desktop、中英文、明暗主题及键盘操作下检查窄宽侧栏、长标题、大量子任务、零任务、失败、结果缺失和刷新状态。实现时再选择组件测试及真实界面验证，不以静态线框替代验收。

本轮只保存界面设计，不修改功能代码，不规定新的后端接口或任务状态。任何实现状态在[功能清单](../../../worktree-feature-list.md)更新，未验证前不得标为完成。
