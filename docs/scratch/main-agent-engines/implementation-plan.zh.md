## 实施前验证

生产实现前，架构评审者必须接受外部历史例外及所选 Codex 通信方式。provider 实施者必须记录固定版本下的恢复、取消、输入接收、item 标识、审批往返及进程退出证据。不支持的能力保持禁用。缺少证据仅阻止依赖它的任务包，不影响独立文档或原生重构。

当前设计足以指导有界任务包，但不足以盲目生成全部适配器。SDK 行为和持久化定义位置是明确的验证关口。源码与拟议 API 冲突时，报告准确冲突并先修订设计，再改变语义。绝不能通过关闭 invariant 或将必需历史设为 ignorable 来消除不匹配。

<a id="ordered-packets"></a>

## 有序任务包

| 任务包 | 依赖与阅读范围 | 产物与退出条件 |
|---|---|---|
| P0：证据 | 现有 Claude/Codex 子代理源码；固定 SDK/协议 | 有 fixture 或真实运行依据的能力表；记录架构选择 |
| P1：路由 | P0 选择；core/agent 和全部 setFactory 调用方 | 具名注册、显式默认值解析、endpoint 感知的模型注册、持久化引擎选择设计；更新原生调用方 |
| P2：生命周期 | P1；core/agent-loop 创建、恢复和投影 | 提取公共生命周期；保持原生创建、回滚、取消和销毁行为 |
| P3：记录 | P1；core/session、session-format、持久化审查 | 必读引擎事件、公共读取投影、outbox 与恢复；兼容确认 |
| P4：API 与 UI | P2/P3；api/session-controller 和 conversation 渲染器 | 引擎目录、引擎选择下拉、按 endpoint 过滤的模型目录、本地化卡片及能力拒绝；模拟引擎端到端可用 |
| P5：Claude | P0/P4；受管 Claude spawn 与 query API | 持久化多轮主聊天、停止、恢复和审批，并有针对性集成证据 |
| P6：Codex | P0/P4；Codex wire 和 app-server 方法 | 持久化多轮主聊天和支持的控制，并有协议证据 |
| P7：分发 | P5/P6；Bundle 组合、TS/Python SDK、快照 | 可选 provider Bundle、保留原生默认值、更新两套 SDK 预期及用户文档 |

P1 必须确定冷恢复如何在选择工厂前读取引擎选择；不能让每个工厂打开同一可写会话来寻找所属者。优先单次只读检查，再取得唯一写入所有权并重新校验标识。P3 实现选定的选择编码，处理检查与写入之间的竞态。两个任务包一致前不得启用外部 provider。

<a id="acceptance-matrix"></a>

## 验收矩阵

| 场景 | 必需证据 |
|---|---|
| 注册两个引擎 | 都能创建主聊天；重复注册被拒绝 |
| 创建后修改默认值 | 已有会话恢复保存的引擎 |
| 原生回归 | 现有创建回滚、setup、inbox、维护和销毁测试通过 |
| 外部两轮对话 | 第二轮感知第一轮上下文，不手工重放 transcript |
| 进程重启 | 恢复同一原生标识；状态丢失明确失败 |
| 投递不确定 | 确认前崩溃不导致自动重复分发 |
| 审批取消 | 取消后旧审批无法执行工作 |
| 外部工具活动 | 一张活动卡片；不经 DSH 工具二次执行 |
| 流重连 | 结算内容只出现一次；临时缺口刷新 |
| 移除 provider | 公共读取方仍可展示历史；继续执行明确失败 |
| 不支持 steering/fork | API 在队列或 seed 变化前拒绝 |
| 运行时清理 | 销毁等待退出，不终止其他 provider 会话 |
| SDK 兼容 | TypeScript 和 Python 预期包含引擎事件及错误 |

用户可见事件序列使用无密钥录制会话 fixture，生命周期行为使用真实进程测试。真实 API 验证是单独的凭证阶段，不可执行时明确报告未运行。遵循[测试政策](../../testing.zh.md)和[推送前检查](../../../.agents/skills/dsh-pre-push-checks/SKILL.md)；不能以全套测试代替针对性的语义证据。本文件列的是计划验证，不是验证结果。

<a id="implementer-handoff"></a>

## 实施者交接

每次分配写明一个任务包、允许文件、前置证据和预期产物。修改前阅读根与子树规范、任务包及引用的所属文档。交接报告变更 API、消费者更新、实际运行测试、未解决事实和下一可执行任务包。核心生命周期及持久化类型未确定前，避免多个 Agent 并行编辑这些接口。

建议任务指令：P0 选择记录完成后只实施 P1；按详细设计实现选择语义；更新每个工厂消费者；保留原生行为；提供针对性路由测试和文档；不添加 SDK 调用、UI 变化或其他引擎回退。评审者检查任务包后再进入 P2/P3。
